# delivery-contract（Codex 版）安装说明

和 Claude 版是同一套交付工作法：访谈 → 验收合同 → 计划 → 实现 → 冻结 → 独立验收 → 诚实报告 → 复盘沉淀行业经验。流程规则和脚本完全一样，只把提问、计划、独立 QA 换成了 Codex 的做法。用的是你的 ChatGPT / Codex 订阅，不额外花钱。

## 安装

任选一种方式。

- 用 [在线安装命令](../README.md#在线命令)，选择 `codex`。安装位置为 `${CODEX_HOME:-$HOME/.codex}/skills/`。
- 下载 [Codex ZIP](https://github.com/znnw4m6k7k-dotcom/dsh-delivery/releases/latest) 中的 `delivery-contract-codex.zip`，解压到 Codex 扫描的技能根目录。项目级安装可以用 `.agents/skills/`。保留整个 `delivery-contract/` 文件夹。

重新加载技能或新开 Codex 会话，输入 `$delivery-contract` 验证技能已加载。

## 使用
- 直接说要交付的东西，或者开头加 `$delivery-contract` 点名调用，例如：`$delivery-contract 帮我做一个电商财务对账工具`。
- 它会先问几轮业务问题（回编号就行，比如 `1A 2C`），列验收条目让你确认后才开工。
- **独立验收**：它会用 `codex exec` 另开一个 Codex 进程来验收。第一次 Codex 会弹出"是否允许在沙箱外运行"，选允许；不允许的话它会改成自己验收，并在报告里写明"非独立验收"。
- 交付后说"做复盘"，候选经验逐条请你确认，确认的才写进 `~/.codex/skills/industry-<行业>-<场景>/`，下个同行业项目自动用上。

## 和 Claude 版的区别
- 没有运行时守卫（Codex 没有拦截工具调用的 hook），改为在关键节点用脚本核对：QA 后必跑 `verify-hash`，报告前必跑 `status`。
- 没有子 Agent 工具，调研和开发由主 Agent 顺序做；需要隔离时用 `codex exec`。

## 维护
Codex 版由 `codex-skill/build.py` 从 `claude-skill/delivery-contract` 生成，不要直接改 `codex-skill/delivery-contract/`。改 Claude 版后运行 `python3 codex-skill/build.py` 重新生成。
