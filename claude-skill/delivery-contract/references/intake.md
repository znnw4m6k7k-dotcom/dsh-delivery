
# 需求访谈与验收草案

## A. 访谈

目标不是“少问”，而是**问到能做出用户真正想要的东西**。只问一两个问题就开工，结果往往是通用模板。

### A1. 先做缺口清单（不发给用户）
按交付物类型，对照下面的维度逐项判断：材料或对话里**已明确 / 可合理假设 / 必须问**。

| 交付物类型 | 必须覆盖的维度 |
|---|---|
| 商业方案 / 开店 / 创业计划 | 谁用这份方案（自己决策、给合伙人、给银行或投资人）；城市和商圈；预算上限和资金来源；品类定位和价格带；经营模式（自营 / 加盟 / 品牌）；店面规模和人手；时间表；个人经验和资源；最担心的风险；交付格式和篇幅 |
| 财务测算 | 测算目的；时间跨度；已知真实数字（租金、报价、薪资）；保守 / 中性 / 乐观是否都要；口径（税前税后、含不含折旧）；需要可改参数还是定稿 |
| 咨询报告 / 调研 | 读者和决策场景；要回答的核心问题；范围边界；可用的数据和访谈对象；结论要多确定（方向性 / 可直接执行）；保密和去标识要求；格式和篇幅 |
| 软件 / 应用 / 工具 | 谁用、在什么场景用；必须有的功能和明确不要的；数据从哪来、存在哪；运行环境；账号和权限；上线方式；验收怎么演示 |
| 其他 | 用途和读者；成功的样子；约束（钱、时间、合规）；交付格式 |

加载了行业经验包（`industry-<行业>-<场景>` 技能）时，把其 `references/intake-questions.md` 里与本项目相关的问题并进清单，标注 `"source":"industry:<lesson-id>"`。

### A2. 分轮提问
- **第 1 轮（必问）**：会改变方案方向的问题，通常 4–6 个。例如开店方案里的城市商圈、预算、模式、用途。
- **第 2 轮（追问）**：根据第 1 轮回答展开，影响质量和可信度的问题，通常 3–5 个。例如已有的真实报价、最担心的风险、交付形式。
- 一般 2 轮，最多 3 轮。每轮结束说明“还剩几个问题”或“问题问完了”。
- 每题尽量给选项和推荐项，并允许用户回答“按你的推荐”或“不确定”。对“不确定”的题目，记成假设并在报告里标出。
- 用户明确说“别问了，直接做”，就停止提问，把剩下的缺口全部写成假设。

每个问题的结构：
```json
{"id":"类别.要点","category":"goal|scale|data|compliance|deliverables|risk|context","round":1,"text":"业务语言的问题","why":"一句话说明这个问题影响什么","options":["选项1","选项2"],"recommended":"选项1","required":true}
```

规则：
- 已回答或材料已说明的不问；纯技术实现自己决定，不问用户。
- 用非技术用户能懂的话；`why` 让用户知道为什么要回答。
- 调研后才能判断的事（例如某商圈租金水平）不要问用户，自己查；查不到再问“你是否知道实际报价”。

### A3. 需求摘要
提问结束后，先用 5–10 行写一份“我理解的需求”：用途和读者、关键约束、已确定的选择、采用的假设（逐条标明）。请用户确认或修改，再进入 B。

## B. 整理验收条目草案
输入：原始请求、全部回答（最新修订在前）、此前讨论、行业经验包的 `references/acceptance.md`（如有）。

每条输出：
```json
{"id":"requirement-1","statement":"可以核对是否完成的要求","sources":[{"kind":"request|answer|discussion|industry","id":"问题 ID 或经验 ID","quote":"逐字引文"}]}
```
规则：
- 优先级：用户最新明确回答 > 原始请求 > 此前讨论。
- 不把问题里的建议、你的假设、未同意的方案当成用户要求。
- **只整理资料中确实存在的要求**，不添加通用质量指标、测试数量、性能目标。
- 行业经验推荐的条目单独列为"建议补充"，用户同意后才进入合同。
- 冲突无法化解时不要擅自选择，列出来问用户。
- 确实没有标准时返回空列表并说明。

### A4. 在 Claude 里怎么问
- Claude Code：用 `AskUserQuestion` 工具，一次最多 4 题，每题 2–4 个选项，推荐项放第一个并在标签后加"（推荐）"；`why` 写进选项说明。一轮超过 4 题就分两次调用。
- claude.ai：在一条消息里用编号列出本轮问题，每题列出选项并标出推荐，最后提示"可以只回编号，也可以回'按你的推荐'"。
- 每轮结束后把问答追加到 `.delivery/interview.jsonl`（一行一题：`{"id","round","text","answer"}`），复盘时要用。

## C. 让用户确认
把草案用表格展示给用户：条目、来源。用户确认、修改或删除后，写入 `.delivery/contract.json` 并设置 `confirmed_by_user: true`，然后运行 `python3 $SKILL/scripts/delivery.py check-contract`。

合同格式：
```json
{"goal":"…","industry":"gov/data-platform","deliverables":["…"],
 "acceptance":[{"id":"requirement-1","statement":"…","source":"request|answer:<问题id>|discussion|industry:<经验id>","quote":"逐字引文"}],
 "assumptions":["…"],"compliance":"internet|gov-cloud|classified|not-assessed","verification":"independent|artifact",
 "confirmed_by_user":true,"confirmed_at":"2026-11-02","confirmation_quote":"用户确认时的原话"}
```
- `confirmation_quote` 必须是用户的原话（如"可以""确认，第3条删掉"），不能是你编的。
- `verification: artifact` 只用于纯 .md/.txt 文档，且要用户明确同意。
- 用户后来改需求：改合同、重新确认，已有冻结版本作废。
