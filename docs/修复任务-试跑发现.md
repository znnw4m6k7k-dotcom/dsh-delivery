# 修复任务：新手试跑发现的两个问题

背景：2026-11-01 用新手身份在交付模式里做了「装修报价单模板」（~/Documents/deepseek/装修报价单模板），28 分钟交付、QA 11/11 通过。但工作区根目录 ~/Documents/deepseek 本身就是奶茶店项目（有 .delivery/），试跑项目在它的子目录里。结果试跑期间的测试命令全部被记进了奶茶店的 .delivery/evidence.jsonl（13:53–13:59 那几条，版本号还是奶茶店的 v1.4），试跑项目自己没有 evidence.jsonl，第一批的证据计数和 R6 重跑拦截在这次实际上没有生效。

约束：不改 DSH 源码，只改 kit/；改完 `cd kit && node --test tests/*.test.mjs` 必须全过；插件版本升到 1.4.1。

## 修复 1（高）：bash 守卫和证据记录定位到正确的项目

现状：`evaluateBash` 和 `tools/result` 里的证据记录都用 `findDeliveryRoot(cwd)`，cwd 是会话目录（工作区根）。命令里写 `cd 装修报价单模板 && pytest ...` 或 `pytest 装修报价单模板/tests` 时，仍然找到工作区根的奶茶店项目。

要求：
- 新增导出函数 `resolveCommandRoot(command, cwd)`：
  1. 命令里有 `cd <目录>`（含 `cd "带空格 目录"`、`cd a && ...`、多个 cd 取执行测试命令之前的最后一个），按 cwd 解析出目标目录，从那里向上找 .delivery。
  2. 否则看命令参数里出现的、在 cwd 下真实存在的路径（相对或绝对），取第一个能找到 .delivery 且比 cwd 的结果更深（更近）的项目。
  3. 都没有，退回 `findDeliveryRoot(cwd)`。
- `evaluateBash`（R1/R3QA/R6）和证据记录都改用它。写文件类守卫（按目标文件路径定位的那部分）不用动。
- 回归测试（新文件 tests/nested-root.test.mjs）：临时目录里建“根目录是项目 A、子目录是项目 B”，两个都有冻结版本；验证 `cd B && pytest`、`cd "B" && pytest`、`pytest B/tests`、`python3 -m pytest B/tests -q` 都记到 B；在根目录直接 `pytest` 仍记到 A；R6 拦截也按 B 判断。

为什么：新手不会主动要求“单独开文件夹/单独开会话”，工作区里同时有多个项目是常态（工作台本来就支持同一工作区多项目切换），证据记错项目会让 QA 计数、R6、工作台全部失真。

## 修复 2（中）：只记录测试类命令

现状：`DIAGNOSTIC_FIRST` 里的 grep、cat、head、which、stat 等只读命令也被记成 diagnostic 证据，试跑里证据文件被大量查看命令灌满。

要求：
- 只读查看类命令（grep/cat/head/tail/wc/pwd/which/type/stat/diff/rg/echo 等）**不记录**，`evidencePurpose` 对它们返回 undefined；它们依然永远不能算 delivery（保留第一批“grep "npm test" 不算验收”的保护）。
- 真正跑测试但不是冻结命令的（pytest、node --test、npm test、python -m unittest 等）仍记为 diagnostic。
- `node -e` / `python3 -c` 这类一次性脚本：仍记为 diagnostic（它们常被拿来手工验证产出）。
- 更新相关测试用例的期望值，并补一条“grep/cat 不产生证据行”的测试。
