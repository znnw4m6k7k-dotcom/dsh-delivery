# 新功能建议：行业经验学习（做完一个项目，下一个同行业项目更好）

> 给 DeepSeek Harness 交付框架加的功能。这是**建议稿**，你确认方向后我再写进最终的技术准则并做出来。
> 日期：2026-11-01

## 一句话

每个项目验收后自动"复盘"，把能复用的经验沉淀进**行业经验包**；下一个同行业项目开始时自动加载经验包，在需求访谈、验收标准、计划、交付各环节用上；结束时再对比"哪些经验有用、哪些错了"，经验包随项目越做越准。

## 借鉴了 OmniAgent 的哪些做法

| OmniAgent 机制 | 用在这里 |
|---|---|
| 锦囊 `armory_manage(save)`：只存"可复用、有适用边界、有经验来源"的做法，排除凭据和客户数据 | 经验包的入库标准 |
| 记忆先 pending、用户确认后才生效；拒绝过的不再提 | 经验审核流程 |
| 锦囊来自别的项目时"只沿用方法，不照搬业务数据，差异仍需重新验证" | 经验使用规则 |
| 记忆事实带置信度、来源、修订号 | 每条经验的元数据 |
| 政务/医疗/法务锦囊 = 提示词 + 合规清单 | 经验包的文件结构 |

OmniAgent 没做、这次补上的是**"用完之后回头打分"**：它只会存新锦囊，不会追踪锦囊在下一个项目里到底有没有用。

## 流程

```
项目 A（如：某区政务数据平台咨询）
  需求访谈 → 合同 → 执行 → 独立验收 → 你批准交付
                                        │
                                        ▼
                               ① 复盘（retro）
                     从合同、决策记录、QA 结果、返工反馈、交付报告中提取候选经验
                                        │
                                        ▼
                               ② 脱敏 + 去重
                     去掉客户名、人名、金额、账号、内部系统名；和已有经验合并
                                        │
                                        ▼
                               ③ 你审核（候选 → 确认 / 修改 / 拒绝）
                                        │
                                        ▼
                     行业经验包 industry-gov  v3 → v4

项目 B（另一个政务项目）
  开始 → ④ 识别行业 → 加载 industry-gov
        → 需求访谈：预置"这类项目客户常卡在哪"的问题
        → 验收草案：推荐上次被证明必要的验收条目
        → 计划：引用适用的经验，标明"沿用方法，业务差异需验证"
        → 交付 → ⑤ 复盘时给每条用过的经验打分（有用 / 没用 / 错了）
```

## 经验包里存什么（6 类）

| 类型 | 例子 | 用在哪个环节 |
|---|---|---|
| 需求模式 | "政务客户第一轮一定会问数据出不出域" | 需求访谈 |
| 验收条目 | "必须提供等保三级测评所需的日志留存截图" | 验收草案 |
| 有效做法 | "先出现状-目标差距表，客户签字后再做方案，返工少" | 计划 |
| 踩坑 | "国产数据库迁移压测要预留两倍时间" | 计划、风险 |
| 交付模板 | 报告章节结构、公文格式 | 产出 |
| 合规清单 | 等保/信创/生成式 AI 备案逐项 | QA |

每条经验带：适用范围（行业、细分场景、规模）、来源项目（脱敏后的编号）、证据（来自哪条决策或哪次返工）、置信度、被使用次数、被证明有用次数、最后更新时间。

## 文件结构（直接用 DSH 原生的 Skill 机制，不用改 DSH）

```
~/.agents/skills/industry-gov/
  SKILL.md              ← 摘要（≤8KB，DSH 会裁剪超长 skill）：何时用、最重要的 10 条经验
  references/
    lessons.jsonl       ← 全部经验（带元数据，机器读写）
    lessons.md          ← 人能读的版本（从 jsonl 生成）
    intake-questions.md ← 需求访谈题库
    acceptance.md       ← 常用验收条目
  checklists/           ← 合规清单
  templates/            ← 报告/方案模板
  CHANGELOG.md          ← 每次复盘改了什么、来自哪个项目
```

## 在 DSH 里怎么实现（分三期）

| 期 | 做什么 | 依赖的 DSH 能力 |
|---|---|---|
| 一期（纯 Skill） | `project-retro` 复盘技能 + `industry-learning` 使用规则 + 一个行业包模板；复盘靠你说"复盘一下"触发 | skill、todo、ask-user |
| 二期（工作流） | 复盘写成 workflow 脚本：并行读取合同/决策/QA/反馈 → `agent()` 带 schema 输出候选经验 → 去重 → 交你审核；新项目开始时自动识别行业 | workflow、subagent、schema |
| 三期（插件） | Host 插件：交付验收后自动弹出复盘；会话开始自动 `agent.inject` 行业包摘要；经验打分统计；脱敏检查做成硬拦截（含客户名就不让入库） | `turn/end` 事件、`agent.inject`、`ctx.tools.guard` |

## 需要你拍板的几个点

1. **经验入库方式**（关键，已发选择卡片）：每条都由你确认 / 自动入库只汇报给你 / 高置信度自动、其他确认。
2. **行业分多细**：我建议两级，"行业/细分场景"，比如 `gov/data-platform`、`gov/oa-integration`。太粗的话经验会互相干扰，太细又攒不起来。
3. **客户数据边界**：默认严格脱敏，经验里不出现任何客户名、人名、金额。如果你希望保留"某类客户"的画像（比如"区县级 vs 市级"），我会做成可选标签。
4. **经验冲突时**：新项目证明旧经验错了，默认把旧的标成"已被取代"并保留历史，不直接删除。
